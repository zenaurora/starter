# 自动更新与新增设置

本文说明 0.4.0 的自动更新与配置行为。呼出时只刷新应用，不失效文件索引；迟到的应用扫描不打断文件搜索；版本比较使用项目自己的解析器。旧配置中的呼出热键、主题、目录、别名、收藏及使用记录继续兼容。专用终端设置已移除，旧终端字段读取时忽略；终端应用需要自行配置为普通应用快捷键。完整更新内容见 [0.4.0 更新说明](releases/0.4.0.md)。

## 一次点击更新

设置页自动检查仍是启动时和每 24 小时一次。检查不会安装。用户点击「下载并更新」后，后台任务执行完整流程，窗口仍可使用；更新期间不会再发起重复检查或安装。

1. 从 GitHub Release 资产中选择当前架构的精确文件名。macOS 使用对应 ARM64/Intel DMG；Windows 默认安装目录下的应用使用 MSI，其他位置使用便携 ZIP。
2. 流式下载，显示进度并支持取消。限制包大小，要求下载字节数等于 Release 中的大小，并匹配 GitHub 提供的 SHA-256 digest。缺少 hash、截断、损坏或非官方资产地址会中止。
3. macOS 只读挂载 DMG，用 `ditto` 将 `Starter.app` 复制到原应用目录旁的临时目录；核对 bundle ID、版本和代码签名，然后卸载 DMG。Windows 便携包只提取 `Starter.exe`，不展开任意压缩路径。此时旧应用仍在运行，准备失败不会退出。
4. 把正在运行的可执行文件复制成独立更新助手，写入安装计划，等待助手报告就绪，主进程再退出。
5. 助手等待主进程完全退出。macOS/便携版把旧应用改名为备份，再将新应用移到原路径。MSI 使用 `msiexec /i … /qn /norestart` 静默安装，保留 Windows Installer 的事务行为；安装日志保存在配置目录的 `update-msi.log`。
6. 新进程成功打开 GPUI 窗口后回写启动确认。macOS/便携版收到确认才删除旧备份；安装或启动失败则恢复旧版本并重新打开。Windows 新进程启动超时会先结束该进程，避免文件锁阻止恢复。MSI 安装失败由安装器回滚；成功安装后的启动失败会记录错误，保留安装器结果。

配置和历史位于系统配置目录，与应用包分离，更新只替换应用文件。错误报告在 `update-result.json`，下一次启动显示上次更新错误。如果恢复失败，错误会给出保留的旧版本路径。下载和准备阶段的失败留在更新页，可重试。

自动更新要求应用所在目录可写。macOS 开发裸进程或仍在只读 DMG 中运行时，会提示先从可写目录里的 `.app` 启动。安装发生在当前运行路径，不会自动切换到另一份 Starter。Windows 安装版识别路径为 `%LOCALAPPDATA%\Programs\Starter\Starter.exe`，与现有 MSI 一致。

未来正式版继续使用 `vX.Y.Z` 标签及现有资产文件命名。GitHub 上传资产后生成 digest，不需要额外更新服务。首次安装旧版本仍按原安装方法进行；此功能在包含本次改动的构建中生效。

## 打开方式

`Config.open_with` 保存「扩展名 → 应用」映射。设置页规范化扩展名并支持应用列表/原生路径选择器；填好规则或快捷键后可以点击添加，也可以直接保存设置；手工配置使用不带点的小写扩展名。

```toml
[open_with]
md = "/Applications/Visual Studio Code.app"
pdf = "Preview"
folder = "Finder"
```

`opening::application_for` 先匹配文件扩展名，再匹配 `*`；文件夹独立匹配 `folder`。应用搜索结果不套用文件规则。规则仅影响 Starter 内 Enter/点击打开文件的行为；定位与复制路径仍使用对应动作。

## 通用全局快捷键

内置入口只有“呼出 Starter”，应用快捷键组以数组存储：

```toml
[[shortcuts]]
hotkey = "Cmd+Shift+K"
applications = ["/Applications/kitty.app", "ChatGPT"]
enabled = true
```

`hotkeys::bindings` 将配置编译成「系统热键 → Toggle/Applications」动作，统一解析 Cmd/Command/Win/Option，检查修饰键和重复组合。`Shell` 按系统返回的热键 ID 路由，注册新组合成功后才撤掉旧组合；任何一步失败恢复之前的注册集合。保存配置失败也恢复原热键。应用组的所有目标同时发起打开，单个目标失败不阻止其他应用启动。旧单应用 `application` 字段仍可读取。

设置页采用快捷键总览与独立编辑器，应用组可单独停用。按键使用分格选择框：默认两个格子，点击「＋」增加，点击「×」移除，最多 5 格，对应四种修饰键和一个普通按键。每格的可搜索列表包含 Cmd/Win、Ctrl、Option/Alt、Shift、字母、数字、方向键、功能键等；格子顺序不限，保存时统一组合顺序。每组必须有一个普通按键及至少一个修饰键，空格子、重复修饰键或多个普通按键会显示错误。未选择的应用快捷键不会自动生成记录。选择过程不捕获用户按下的组合键，也不暂停现有全局热键；只有保存后才更新注册。`Esc` 优先关闭下拉菜单，再退出设置。操作系统保留的组合或其他软件占用的组合可能无法注册，保存时会显示具体失败信息。

## 开机自启动

`launch_at_login` 默认 `false`。在“设置 → 启动”开启并保存后，macOS 写入当前用户的 `~/Library/LaunchAgents/dev.starter.launcher.plist`，Windows 写入当前用户的 `Software\Microsoft\Windows\CurrentVersion\Run` 项。注册的命令使用当前应用路径及 `--background`，登录后只驻留托盘。关闭并保存会移除对应登记，取消设置不修改登记。配置保存失败时恢复原自启动状态和快捷键；后台启动遇到错误时显示错误窗口。

## 验证

`cargo test --locked --all-targets` 覆盖版本解析、配置兼容、规则优先级、热键回滚、下载完整性和取消、安装失败和启动失败回滚。macOS 测试生成带签名的临时 DMG，验证准备成功和版本不匹配中止；Windows 测试确认 ZIP 中其他路径不被提取。

`python3 scripts/test-macos-updater.py` 在临时应用副本上运行真实更新助手，验证等待退出、替换、重新启动、启动确认和备份清理，不修改 `/Applications`。
