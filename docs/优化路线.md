# 性能优化记录

2026-10-12。优先保证响应速度，允许适量内存用于热缓存。保留文件索引、图标缓存和中文输入/全屏窗口策略。

2026-10-14 版本说明：下文记录的是 10 月 12 日的优化对照及测量。随后纠错逻辑又调整为仅对 4–31 字符查询启用，并在首个容差内匹配时返回，不再求所有单词的最小距离。这可能影响部分纠错结果的相对顺序；下表不是这一后续实现的重新测量结果。

## 实际路径

- 启动：main 创建窗口 → Launcher::new 启动后台工作线程 → 应用目录扫描完成后更新候选。监控线程在面板关闭时阻塞，不采样；文件索引直到首次 /f 查询才建立。
- 应用输入：InputEvent::Change → Launcher::search → 应用候选与内置命令的借用迭代器 → 排名 → 克隆最多 100 条结果供 UI 显示。
- 文件输入：取消旧查询 → 单个搜索线程 → 复用文件索引 → 排名 → Results/Done。应用扫描不清空文件索引；明确刷新或搜索目录改变才重建。
- 内容输入：同一工作线程执行 50 ms 去抖和可取消文件扫描，分批返回。继续不缓存文件内容。
- 监控：每秒生成一次不可变快照；渲染时排序行索引，虚拟列表共享该帧快照，只读取可见行。

## 本次优化

1. 文件索引保存一份完整路径、类型，以及原始/归一化文件名缓存。删除常驻索引中重复的 ID 路径和父目录字符串，只为最终结果生成完整 Candidate。保留短文件名缓存，因为反复解析路径、转换大小写会增加每次输入的开销。
2. 排名分批裁剪至前 100 条，最多保留 4096 条打分记录；全局排序仍按相关性、收藏、频率、最近使用、名称和身份决定。空查询不创建模糊匹配器。应用和文件共用一套排名逻辑。
3. 纠错使用同一 Damerau–Levenshtein 算法，前缀直接借用原字符串，复用重复距离结果，避免对完整单词重复计算。
4. 应用搜索借用候选，内置命令通过 LazyLock 构造一次，删除每次输入时的整表克隆和命令文本重建。
5. 文件名查询删除固定 50 ms 等待；内容搜索保留去抖。应用扫描和完整刷新合并为同一发现流程，保留各自的缓存失效语义。
6. 后续调度会释放已完成的 GPUI 任务句柄，保留运行中任务在窗口关闭时的取消行为。150 ms 失焦宽限和 generation 机制继续保留。
7. 监控虚拟列表共享 Arc<Snapshot>，删除整份进程列表的逐帧深克隆；空筛选不再给所有进程名称转小写。

## 可重复测量

```sh
cargo run --release --locked --example performance -- 98000
```

基准创建临时文件、调用生产搜索代码，退出时删除临时数据，不访问用户文档。98,000 个文件加 1,960 个目录，共 99,960 条索引；应用场景含 500 条候选。比较使用同一台 Mac、release 配置和计数分配器，预热后重复查询。下列为一次前后对照，毫秒数受机器负载影响。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 文件索引保留的 Rust 堆 | 47.23 MiB | 25.56 MiB |
| 空文件查询计算 | 3.643 ms | 3.700 ms |
| 文件查询 report | 13.931 ms | 10.690 ms |
| 文件纠错查询 rpeort | 121.421 ms | 92.643 ms |
| 中文文件查询 项目 | 3.669 ms | 1.599 ms |
| 无命中文件查询 zzzzzzzz | 133.259 ms | 80.640 ms |
| 匹配文件查询的额外堆峰值 | 9,709.9 KiB | 495.1 KiB |
| 默认应用列表计算 | 0.140 ms | 0.065 ms |
| 默认应用查询累计分配 | 357.3 KiB | 76.9 KiB |

文件计算时间不包含工作线程、UI 调度或之前的 50 ms 固定等待。堆计数不等于整个应用 RSS：GPU、系统框架、图标、剪贴板、线程栈和分配器保留页面不在这些数值中。纠错仍使用完整距离计算，极大索引上的无命中查询仍有优化空间。

## 保留与验证

- 保留热索引、原始/归一化文件名和图标缓存，用适量内存换取输入响应速度。
- 保留中文别名、收藏/频率/最近使用的排序、历史配置兼容、内容文件大小与二进制限制，以及取消标记和过期结果过滤。
- 不增加文件内容缓存、索引落盘或文件监听器。本次没有引入持久化格式、后台常驻扫描或新依赖。
- 移除旧 rank_cancellable 转发入口；其唯一生产调用已迁入 FileIndex::search。取消行为由文件查询测试继续覆盖。
- 新增全局前 100 名/身份排序、中文文件身份/目录类型/重叠目录、工作线程缓存刷新和连续操作任务句柄回归测试。原有配置、中文输入、卸载、更新和监控行为测试保留。
- 验证命令：cargo fmt --check、cargo clippy --locked --all-targets -- -D warnings、cargo test --locked --all-targets。macOS 系统剪贴板、废纸篓、DMG 和本机 HTTP 测试需要沙盒外的系统访问。
- 本轮 macOS 验证通过：54 个库测试、29 个应用测试，共 83 个；格式检查、Clippy 和差异空白检查通过。未实测 Windows，也未测量完整应用启动/驻留 RSS 或输入到绘制的延迟。

后续优化先测量应用扫描、启动/驻留 RSS 和真实输入到绘制的延迟，再决定是否需要文件监听、索引持久化或更复杂的并行查询。不能把上述搜索微基准当成整个应用的性能数据。
